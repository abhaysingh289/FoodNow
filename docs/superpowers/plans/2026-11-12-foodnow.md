# FoodNow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build FoodNow, a local, single-app food-delivery marketplace prototype (HK/SG). It has a customer app, an ops console that plays restaurant, rider and payment provider, a provider-neutral payment adapter with a fake provider, and asynchronous refunds.

**Architecture:** One Next.js App Router project. All business rules live in `src/modules/*` (catalog, cart, orders, delivery, payments, simulation). Route handlers are thin wrappers. Order status changes only through one transition engine driven by an action-keyed state table. Payments talk to the rest of the app only through the `PaymentProvider` interface and signed webhooks.

**Tech Stack:** Next.js 15 (App Router) + React 19 + TypeScript (strict), Prisma 6 (≥ 6.2) + SQLite, Tailwind CSS, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-12-foodnow-design.md`. Read it alongside this plan. Section numbers (§) below refer to it.

## Global Constraints

- Node ≥ 20. TypeScript `strict: true`. Path alias `@/*` → `src/*`.
- Prisma pinned to `^6.2` (JSON columns on SQLite). Status/enum-like columns are `String` in Prisma; their allowed values are TS union types in code.
- Money is integer cents everywhere. Rounding is `Math.round` (half-up for positives), applied once per computed line: discount, delivery fee, tax.
- Country config is verbatim from §6:
  - HK: `HKD`, display `HK$`, tax 0, fee `1000 + 300/km`, cap `3500`.
  - SG: `SGD`, display `S$`, tax `0.09`, fee `200 + 60/km`, cap `700`.
- Order statuses are verbatim from §10.1: `PENDING_PAYMENT, PAYMENT_FAILED, PLACED, ACCEPTED, RIDER_ASSIGNED, PICKED_UP, DELIVERED, CANCELLED, REFUND_PENDING, REFUNDED, REFUND_FAILED`.
- Actors: `CUSTOMER | OPS | AUTO | PROVIDER | SYSTEM`.
- Failure reasons: `RESTAURANT_REJECTED | CUSTOMER_CANCELLED | NO_RIDER | DELIVERY_FAILED | PAYMENT_ABANDONED`.
- Every API error body is `{ "error": { "code": "<UPPER_SNAKE>", "message": "<human text>" } }`.
- Route handlers contain no business rules. They parse input, call one module function, and map the result.
- Only `src/modules/orders/transition.ts` writes `Order.status`.
- Only `src/modules/payments/fake/**` reads or writes `FakeProvider*` tables. Other code uses the functions it exports.
- In Next 15, route and page `params` / `searchParams` are Promises and must be awaited.
- Session cookies are `fn_user`, `fn_country`, `fn_address`.
- Env vars: `DATABASE_URL`, `PAYMENT_PROVIDER` (default `fake`), `FAKE_WEBHOOK_SECRET`, `APP_BASE_URL` (default `http://localhost:3000`).
- Polling: customer tracking and ops board every 2 s. Simulation tick every 1 s while auto mode is on.
- All images are local placeholders under `public/images/`. No external image URLs.
- Commit after every task. Messages use the `feat:` / `test:` / `chore:` prefixes and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Stale session cookies.** After switching user or country, the `fn_address` cookie can point at another user's address or another country's. The session must fall back to the user's first address in the current country instead of pricing against the wrong location. Test in Task 4.
2. **Checkout submitted twice** (double click, or two tabs). The second `placeOrder` must fail with `CART_CONFLICT` ("Your cart is empty") and must not create a second order or charge. Test in Task 9.
3. **Rider conflicts.** Assigning a rider who is busy, or who belongs to the other country (two ops tabs, stale board), must fail with `RIDER_UNAVAILABLE` and leave the order in `ACCEPTED`. Test in Task 7.
4. **Promo stops qualifying.** If a cart edit drops the subtotal below a promo's minimum spend, the cart must show the promo as not applied, with the reason and a discount of 0, rather than error. Checkout must then refuse with `PROMO_INVALID`. Tests in Task 5.
5. **Reorder from a restaurant that's now closed, or whose items are all unavailable.** Reorder must fail with `RESTAURANT_CLOSED`, or report every item as skipped, rather than building an empty or uncheckoutable cart. Test in Task 5.

### Task 5: Cart module (pricing, cart operations, reorder)

**Files:**
- Modify: `src/modules/cart/pricing.ts`
- Create: `src/modules/cart/{cart.ts,reorder.ts,index.ts}`

**Interfaces:**
- Consumes: `prisma`, `COUNTRY_CONFIG`, `formatMoney`, `haversineKm`, errors.
- Produces:
  - `type PromoRule = { code: string; type: "PERCENT"|"FLAT"|"FREE_DELIVERY"; value: number; minSubtotalCents: number; maxDiscountCents: number|null }`
  - `type PriceBreakdown = { subtotalCents; discountCents; deliveryFeeCents; taxCents; totalCents; distanceKm; promoCode: string|null; promoError: string|null }`
  - `computePrice(input: { lines: { unitPriceCents: number; qty: number }[]; promo: PromoRule|null; distanceKm: number; country: CountryCode }): PriceBreakdown`. If the promo doesn't qualify, `promoError` is set and the discount is not applied.
  - `deliveryFee(distanceKm: number, country: CountryCode): number`
  - `type CartView = { restaurant: { id; name; country; isOpen } | null; lines: { id; menuItemId; name; qty; unitPriceCents; options: { id; name; priceDeltaCents }[]; note: string|null; isAvailable: boolean }[]; price: PriceBreakdown }`
  - `getCart(userId: string, address: Address): Promise<CartView>`
  - `addItem(userId, input: { menuItemId: string; qty: number; optionIds: string[]; note?: string; replaceCart?: boolean }): Promise<void>`
    - Different restaurant without `replaceCart` → `CartConflict("Your cart has items from {name}")`
    - Unavailable item → `ItemUnavailable`
    - Closed restaurant → `RestaurantClosed`
    - Bad option selection → `ModifierSelectionInvalid`
    - Qty must be 1–20, else `ValidationError`
  - `updateQty(userId, lineId, qty: number): Promise<void>`. 0 removes the line; 1–20 is valid; otherwise `ValidationError`.
  - `setPromo(userId, code: string|null, country: CountryCode): Promise<void>`. An unknown code for that country throws `PromoInvalid("Promo code not found")`. Minimum spend is not checked here; `computePrice` reports it.
  - `clearCart(userId): Promise<void>`
  - `reorder(userId, orderId): Promise<{ skipped: string[] }>`. Replaces the cart with available items only. Throws `RestaurantClosed` if the restaurant is closed, `NotFound` if the order isn't the user's.

  - `updateSettings(patch: { autoMode?: boolean; stepDelaySeconds?: number }): Promise<…>`. A delay outside 1–60 → `ValidationError`.
  - `tick(now?: Date): Promise<{ advanced: string[] }>`. Returns order IDs or fake refs advanced. When `autoMode` is false it returns `{ advanced: [] }`.
